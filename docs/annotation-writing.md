# 點寫解釋（AI 標註）

**你嘅判斷佔一半分,你嘅解釋佔另一半。**

評審睇你嘅解釋,唔係為咗知你揀邊個 —— **係為咗知你係咪有理由咁揀。** 一個啱嘅判斷配一句空泛解釋,分數低過一個有理有據嘅判斷。

---

# 一、好解釋嘅四段骨架

每次都跟呢個次序,你就唔會漏嘢：

```
① 判斷      邊個好啲
② 證據      引用對方原文,指出具體邊句有問題
③ 事實      正確嘅係咩
④ 來源      邊度查到
```

**四樣缺一唔可。** 最多人漏嘅係 ② 同 ④。

---

# 二、差 vs 好（對比睇最快）

## 示範題目（同你手上嗰條無關）

> **Prompt**: What is the tallest mountain on Earth?
>
> **Response A**: Mount Everest, at 8,849 m above sea level, is the tallest mountain on Earth.
>
> **Response B**: Mount Everest is the tallest at 8,849 m. It was formed about 10,000 years ago when the Indian and Eurasian plates collided.

### ❌ 差（呢啲會扣分）

```
A is better, it's more accurate.
```
→ 空泛。冇講邊度錯,冇來源。**呢種答案睇落同冇答一樣。**

```
I prefer A because B has too much unnecessary information.
```
→ 主觀,而且**答錯咗題**。題目問準確性,唔係問長短。

```
B is wrong.
```
→ 冇講邊句錯、點解錯、正確係咩。

### ✅ 好

```
Response A is more accurate.

Both correctly identify Mount Everest at 8,849 m, so the difference is in
Response B's additional claim. B states the mountain "was formed about
10,000 years ago when the Indian and Eurasian plates collided." The
collision is right, but the timing is wrong by several orders of
magnitude: the India–Eurasia collision began roughly 50 million years
ago, and Himalayan uplift has continued since. 10,000 years ago is the
early Holocene, long after the range existed.

Response A adds no unverified claims, so it contains no errors.

Source: USGS, "The Himalayas: Two continents collide" —
pubs.usgs.gov/gip/dynamic/himalaya.html
```

**點解呢個好：**

| | |
|---|---|
| ① 判斷清楚 | 第一句就講咗 |
| ② 引咗原文 | 「was formed about 10,000 years ago」加引號 |
| ③ 講咗正確事實 | 5,000 萬年,唔係一萬年 |
| ④ 有來源 | USGS,而且係具體嗰版 |
| 額外加分 | **講咗兩個回應相同嘅部分**,證明你逐句對過,唔係憑感覺 |

# 三、六個常見扣分位

| 扣分位 | 點解錯 | 點改 |
|---|---|---|
| 「寫得清楚啲」「好啲」 | 空泛,唔係證據 | 引用具體句子 |
| 「我覺得 / 我鍾意」 | 主觀。佢要客觀判斷 | 用「the claim that... is inaccurate because...」 |
| 只講結論唔講證據 | 評審睇唔到你嘅推理 | 加 ②③ |
| 冇來源 | **通常係硬性計分項** | 一定要有 |
| 捉到一個錯就收工 | 另一個回應可能都有錯 | **兩邊都要逐句查** |
| 前後唔一致 | 第 1 題嚴、第 7 題鬆 | 見下面第六節 |

# 四、幾長算啱

**3–6 句通常啱晒。**

- 太短（一兩句）→ 睇落似冇做功課
- 太長（成篇文）→ 唔會加分,而且浪費你時間（你係計時薪）

**判斷標準**：一個唔認識呢個題目嘅人,睇完你段嘢應唔應該完全明白你點解咁揀？

# 五、來源點寫

## 來源可信度排序

```
官方機構（NASA、USGS、政府、大學）
    ↓
同行評審論文、權威百科（Britannica）
    ↓
維基百科  ← 可以用嚟搵線索,但最好去追佢個引用來源
    ↓
一般新聞
    ↓
❌ 隨機 blog、內容農場、AI 生成嘅站
```

## 格式

```
Source: NASA, "Olympus Mons" — [連結]
```

**要有：機構名 + 頁面標題 + 連結。** 淨係貼條 URL 都得,但寫埋機構名睇落專業好多。

⚠️ **唔好靠記憶。** 就算你好肯定,都要真係開個網頁確認。評審有時會核你嘅來源。

# 六、⭐ 前後一致 —— 呢個最影響長期評分

平台睇嘅唔止係單題準確,**係你成套標準穩唔穩定**。

## 實際做法：開一個記事本

做第一題嗰陣,寫低你嘅標準：

```
我的標準（第一次做時定,之後照跟）
─────────────────────────────
- 事實錯誤 = 最重,一個錯就足以判輸
- 資料過時 = 中等
- 唔完整但冇錯 = 輕微
- 太長 / 太短 = 唔影響「準確性」評分
- 兩個都有錯 → 比較錯得幾嚴重、幾容易誤導人
```

**之後每題照呢張紙判。**

呢個係最容易被忽略、但最影響你之後有冇任務派嘅嘢 —— 因為佢哋就係想搵一個判斷穩定嘅人。

# 七、四種難處理嘅情況

## 1. 兩個都有錯

```
Both responses contain errors. A states [X], which is incorrect because
[Y]. B states [Z], which is also incorrect.

A is the better of the two because its error is [less severe / less
likely to mislead a reader], whereas B's error would lead someone to
[具體後果].

Sources: [兩個都俾]
```

**唔好因為兩個都錯就唔敢揀。** 講清楚點解「錯得少」。

## 2. 兩個都啱,但一個完整啲

```
Both responses are factually correct and I could not find any errors in
either. A is more complete: it also mentions [X], which is directly
relevant to the question. B omits this but states nothing false.

Source: [確認兩者都啱嘅來源]
```

⚠️ **「兩個都啱」係一個合法答案。** 唔好為咗顯得勤力而屈一個錯出嚟。

## 3. 一個準確但難讀,一個易讀但有錯

**先睇份準則問緊咩。**

- 問「accuracy」→ 準確嗰個贏,但可以喺解釋度提一句可讀性
- 問「overall quality」→ 就要衡量,而且要寫明你點衡量

```
B is easier to read, but A is more accurate, and the rubric asks for
accuracy. B's claim that [X] is incorrect [原因]. Readability does not
offset a factual error in a factual question.
```

## 4. 你查極都查唔到

```
I could not verify [具體聲稱] against any authoritative source. I
searched [講你搵過乜]. Because this claim is unverifiable rather than
demonstrably false, I have weighted it as a minor concern rather than an
error.
```

**老實講「查唔到」好過亂估。** 呢種答案評審通常會接受,而且顯示你有做功課。

# 八、一個可以直接改嘅骨架

```
Response [A/B] is more accurate.

Both responses correctly state [相同嘅部分]. The difference is in
[分歧點].

Response [X] claims "[直接引用]". This is incorrect: [正確事實].

Response [Y] makes no claims that I could not verify.

Source: [機構], "[標題]" — [連結]
```

**把括號填滿就係一個合格答案。** 熟咗之後你會自然變化,唔使死跟。

---

# 九、實際操作習慣

```
□ 兩個回應逐句對,圈出「唔同」嘅部分
□ 相同嘅部分唔使查（省時間）
□ 每個唔同嘅事實聲稱 → 開個 tab 查
□ 查嗰陣順手複製條 URL,唔使返轉頭再搵
□ 寫解釋,跟四段骨架
□ 交之前重讀一次：一個外行人睇唔睇得明我點解咁揀？
```

⚠️ **唔好趕。** DataAnnotation 明文講佢哋睇**仔細同準確,唔係速度**。頭幾題慢慢做,熟咗自然會快。

# 十、記住點解佢哋請你

**佢哋唔係想要一個「答案」。** 答案 AI 自己有。

**佢哋想要嘅係一個人,肯逐句查、肯講「呢句錯咗,正確係咁,來源喺呢度」。**

你嘅解釋就係佢哋買緊嘅嘢。寫得好,你會由「一般任務」升到「高薪項目」;寫得馬虎,任務會慢慢少。

**呢個亦係點解唔可以用 AI 幫你寫解釋** —— 用咗,你就唔再係佢哋買緊嗰件嘢。

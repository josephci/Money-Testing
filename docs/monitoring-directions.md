# Part 1：「佢哋自己做到」呢個問題

## 先換個問法

「佢自己做唔做到？」—— **呢個問題本身係錯嘅。**

人人自己煮到飯,餐廳一樣賺錢。人人剪到頭髮,髮型屋一樣賺錢。

正確嘅問題係：

> **「呢個問題對佢嚟講,值唔值 $29？」**

如果你要靠「佢技術上做唔到」嚟守住個生意,你已經揀錯客 —— 因為總有一日佢會識,或者出個工具幫佢做到。

**你要嘅位置係：佢做得到,但做落唔化算。**

---

## 八個佢會俾錢嘅真實原因

### 1. 做得到 ≠ 會去做 ⭐最重要

「技術上可行」同「真係有人持續做咗兩年」之間,差咗一個深淵。

監察類尤其明顯 —— 人手監察要**記得去 check**。實測落嚟,人手每日檢查一個網頁,大部分人兩個星期內就會斷。之後就係「哦我上個月冇睇到」。

**你賣嘅唔係功能,係「唔使再記住呢件事」。**

### 2. 你嘅買家根本唔識 code ⭐最重要

呢個係最大嘅槓桿,亦都係**揀客時最應該優先考慮嘅一件事**。

賣俾程式員 → 佢真係一個週末砌到,你好難收錢。
賣俾地產經紀、獵頭、律師行文員、餐廳老闆、採購 → 佢**連 cron job 係咩都唔知**。

> 呢個唔係睇小人。專業分工就係咁 —— 你都唔會自己報稅、自己驗車。

**推論：主動揀非技術買家。** 呢一個決定,就解決咗你八成嘅「點解唔自己做」疑慮。

### 3. 佢嘅時間本身有價

一個時薪 $50 嘅自由工作者,每月花 3 個鐘手動檢查 = **$150 嘅時間成本**。

你收 $29,佢慳 $121。呢條數佢一秒就計得出。

⚠️ 但呢個論點**只喺買家靠呢件事搵錢時先成立**。所以之前份計劃話「揀靠呢件事搵錢嘅客」—— 唔係要你揀有錢人,係要令呢條數計得掂。

### 4. 你賣嘅係「一直運作」,唔係嗰段 code ⭐

**寫一個爬蟲：30 分鐘。維持佢兩年唔死：先係真正嘅工作。**

DIY 嗰個人以為自己買咗 30 分鐘嘅工作,實際上佢簽咗一份長期合約:

- 對方改版 → 爛
- 對方加 IP 限制 / 驗證碼 → 爛
- 佢自己部電腦熄咗 / 續費失敗 → 靜靜哋停咗,佢仲以為運作緊
- Email 入咗垃圾箱 → 收唔到通知
- 要加多 10 個來源 → 又要重寫

**最陰險嗰個係「靜靜哋停咗」。** DIY 方案唔會通知你佢死咗,你只會喺漏咗一單生意之後先發現。

你賣嘅承諾係：**十八個月後佢一樣照跑,而你唔使諗過。**

### 5. 建立係一次,維護係一世

呢個係唯一連**技術買家**都殺得死嘅論點。

程式員唔係諗「我砌唔砌到」,係諗「我想唔想未來三年每次爛都要修」。好多人寧願俾 $29 都唔想再孭多一個要維護嘅嘢。

### 6. 買 = 今日就有,砌 = 永遠都係「下個週末」

「我遲啲自己整」= 永遠唔會整。

你賣嘅係**即刻解決**。呢個溢價真實存在。

### 7. 歷史數據會累積,而且追唔返 ⭐

如果你由第一日開始記錄,一年後你有**一年嘅歷史數據**。

佢今日先自己砌,只有由今日開始嘅數據 —— **過去嗰年佢永遠追唔返。**

「呢個對手過去 12 個月改過幾多次價」呢類問題,只有你答到。

**呢個護城河會隨時間自動變深,係監察類生意最抵玩嘅特性。**

### 8. 匯總本身就係產品

佢自己盯 **1 個**來源,勉強做到。
你幫佢盯 **40 個**來源,統一格式、去重、排優先次序。

由 1 個到 40 個唔係難 40 倍,係難 400 倍 —— 而價值正正喺呢度。

## Buy vs Build 評分表

有新 idea 就打分,滿分 8：

| 問題 | 答「係」得分 |
|---|---|
| 買家係**唔識 code** 嘅人？ | **+2** |
| 漏咗嘅代價高（罰款、蝕單生意、失去客戶）？ | **+2** |
| 資料來源會變,要長期維護？ | +1 |
| 要匯總多個來源（5 個以上）？ | +1 |
| 歷史數據會累積價值？ | +1 |
| 早幾個鐘知道 = 直接賺錢？ | +1 |

**5 分以上** → 買 vs 砌嘅論述好穩,放心做
**3–4 分** → 得,但要揀窄啲嘅市場
**2 分或以下** → ❌ 唔好做,你會不停被人問「點解我唔自己做」

## 🚩 死亡組合

**技術買家 + 問題簡單 + 價值低** = 冇得救。

三樣入面至少要破一樣：買家唔識 code、問題真係難、或者價值夠高。

> ⚠️ 呢啲係**方向**,唔係已驗證嘅 idea。落手前一定要行返份計劃嘅驗證步驟（Fiverr 睇需求、社群蹲點、傾 5 個真實用戶）。

## 1. 招標 / 政府採購公告監察 ⭐ 8/8

**盯咩**：政府採購網、公營機構、大企業供應商門戶嘅新招標公告,按行業/金額/地區過濾。

**買家**：承包商、工程公司、IT 供應商、清潔/保安公司、翻譯社。

**點解會買**：
- **一單標可能值幾十萬。** 對比之下 $99/月完全唔使諗
- 公告有截止日期 —— **漏咗就係零**,冇得補
- 招標資訊散落幾十個唔同網站,冇人有時間逐個 check
- 買家係做工程做生意嘅人,唔係程式員
- 政府網站個個介面唔同、成日改版 → 維護成本高 = 你嘅護城河

**呢個係全部入面 buy-vs-build 論述最強嘅一個** —— 因為單次價值高到離譜,而漏咗嘅代價係 100%。

**風險**：部分地區已有成熟商業服務(收費好貴)。你嘅切入點係**做窄** —— 專攻一個行業、一個地區,收得平好多。

---

## 2. 監管 / 牌照 / 合規更新監察 ⭐ 8/8

**盯咩**：政府部門公告、牌照續期、規例修訂、標準更新、進出口管制清單。

**買家**：食肆、診所、財務顧問、進出口貿易商、小型律師行、裝修承辦商。

**點解會買**：
- **漏咗嘅代價 = 罰款、停牌、封舖。** 恐懼係最強嘅付費動機
- 買家係全世界最唔技術嘅一批人
- 政府網站嘅 HTML 亂到癲、成日改 → DIY 方案死得特別快
- 呢筆錢對佢哋嚟講係「保險」,唔係「工具」—— 保險嘅價格敏感度低好多

**風險**：
- ⚠️ **絕對唔可以俾人覺得你喺度提供法律意見。** 你只係做「通知有嘢更新咗」,唔係「解釋條例點解讀」。呢條線要劃得好清楚,文案上要寫明
- 要揀你真係識嘅行業,否則你連過濾都做唔準

---

## 3. 招聘職位空缺監察 ⭐ 7/8

**盯咩**：目標公司嘅 career page、LinkedIn、行業招聘板 —— 邊間公司開始請人、請緊咩職位。

**買家**：獵頭、招聘代理、人力資源顧問。

**點解會買**：
- **一單 placement 佣金成幾萬蚊。** 早三個鐘知道 = 攞到單
- 呢行速度就係一切,「第一個打去」同「第二個」係天堂同地獄
- 要同時盯 200 間公司 —— 人手絕對做唔到
- 獵頭係銷售型人格,唔係技術人

**額外角度**：唔止「請緊人」,仲可以盯「**某公司突然大量招聘**」= 佢哋擴張緊 = 商機信號。呢個推導出嚟嘅情報,比原始數據值錢好多。

**風險**：留意各平台嘅服務條款,盡量用官方 API 或者公開嘅 career page。

---

## 4. 競爭對手價格 / 斷貨監察 ⭐ 7/8

**盯咩**：對手嘅 SKU 價格、庫存狀態、上新、促銷。

**買家**：Shopify / Amazon / 淘寶 賣家。

**點解會買**：
- **定價直接等於利潤**,呢條數佢好清楚
- 要盯 200 個 SKU,唔係 1 個 —— 規模就係價值
- **價格歷史係最強嘅累積護城河**：「對手過去半年減過幾多次價、通常幾時減」呢啲問題,新入場者永遠答唔到
- 賣家係做生意嘅,唔係寫 code 嘅

**風險**：⚠️ **呢個賽道競爭最激烈**,已經有好多成熟工具。切入方法係**極窄**：專攻一個品類、一個平台、一個地區,做到大工具唔屑做嗰種細緻度。

---

## 5. 資助 / 撥款 / 比賽申請截止監察 ⭐ 7/8

**盯咩**：政府資助計劃、基金會撥款、創業比賽、研究經費嘅新開放同截止日。

**買家**：NGO、學術研究員、初創、社企、藝術團體。

**點解會買**：
- **一個資助可能係六位數。** ROI 唔使計
- 硬截止日期,漏咗要等下一年
- 資訊散落幾十個機構網站,格式各異
- 買家係做社福/研究/創作嘅人,零技術

**風險**：NGO 預算緊,價格敏感。可以考慮年費模式($199/年)一次過收,慳手續費又符合佢哋嘅預算週期。

---

## 6. 客戶網站健康監察 + 白牌報告 🟡 5/8

**盯咩**：客戶網站 uptime、SSL 證書到期、域名到期、載入速度、SEO 基本項。

**買家**：自由接案網頁設計師、細 agency。

**點解會買**：
- 佢管住 30 個客戶網站,唔係 1 個
- **白牌月度報告**可以直接發俾佢自己嘅客 → 你幫佢賣緊嘢,唔止幫佢慳時間
- 出事有人孭飛

**點解評分低**：⚠️ 買家**半技術**,而且呢個市場飽和(UptimeRobot 等一大堆,仲有免費)。

**唯一值得做嘅角度**：唔好賣「監察」,賣「**白牌客戶報告**」—— 幫佢喺客戶面前顯得專業。呢個部分先係佢肯俾錢嘅嘢。

---

## 7. 二手市場 / 收藏品筍盤監察 🟡 5/8

**盯咩**：二手平台、拍賣網,符合特定條件(型號+價格區間+地區)嘅新上架。

**買家**：轉售者、收藏家。

**點解會買**：套利要快,慢五分鐘個筍盤已經俾人買咗。要同時跑 50 個搜尋條件。

**點解評分低**：偏向消費者市場,**價格承受力低**($19 都嫌貴),而且部分人自己會搞。

**只值得做嘅切入點**：專攻**靠轉售搵錢**嗰批人(唔係興趣收藏家)。佢哋計 ROI,肯俾錢。

# Part 3：點揀

### 揀嘅次序

1. **由「你熟嘅行業」出發**,唔好由「技術有趣」出發
   → 你識嗰行,你先知邊個公告重要、邊個係雜訊。過濾準確度就係產品質素
2. 用上面嘅評分表打分,**5 分以下唔好做**
3. 去嗰行嘅社群蹲一個禮拜,搵「重複性怨言」
4. 傾 5 個真實用戶先寫第一行 code

### 落手前嘅檢查

- ⚠️ 抓取前睇清楚對方 ToS 同 `robots.txt`,有官方 API 就用官方 API
- ⚠️ 政府/公開資料通常最安全,商業平台要小心
- ⚠️ 通知類服務要留意個人資料同反垃圾郵件嘅規定

### 應對「我自己做到喎」嘅回答

客真係問起,唔好爭辯佢做唔做到。直接講:

> 「你梗係做到。問題係你想唔想未來三年,每次個網站改版都要你去修佢 —— 而且佢爛咗嘅時候唔會通知你,你只會喺漏咗一單之後先發現。」

**承認佢做得到,然後將對話由『能力』移去『代價』。** 呢個先係你真正贏嘅戰場。

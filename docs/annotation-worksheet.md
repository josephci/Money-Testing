# 標註工作紙（開住佢做嘢）

**呢份唔係用嚟讀,係用嚟開住。** 每題照跟,唔使再由零諗。

目標：**第 3 題就達到人哋第 10 題嘅速度。**

---

# 一、每題固定 6 步（連時間預算）

```
① 讀 prompt + 兩個回應,圈低「唔同」嘅地方        2 分鐘
② 只查唔同嗰啲                                  3–4 分鐘
③ 決定（先決定,唔好一路寫一路諗）                30 秒
④ 照範本寫                                      2–3 分鐘
⑤ 貼來源                                        30 秒
⑥ 對返份準則打勾,交                             1 分鐘
                                          ─────────────
                                          約 8–10 分鐘
```

**如果邊一步超時好多,就係嗰步有問題** —— 睇返下面對應嗰節。

---

# 二、⭐ 最大嘅省時位：只查「唔同」嘅嘢

新手最慢嘅原因係**由頭到尾逐句查**。唔使。

```
兩個回應相同嘅部分  →  唔使查（佢哋唔會因為呢度分高下）
只有一邊出現嘅聲稱  →  ★ 全部要查
兩邊都有但講法唔同  →  ★★ 最重要,通常答案就喺呢度
```

**做法**：讀嗰陣開個記事本,打三行 —— 相同 / A 獨有 / B 獨有。之後只查後面兩行。

呢一招通常慳一半時間。

---

# 三、查證捷徑

## 按題材直接去邊度（唔使諗）

| 題材 | 直接去邊度 |
|---|---|
| 太空、行星、天文 | NASA (`site:nasa.gov`) |
| 地質、地震、山、火山 | USGS (`site:usgs.gov`) |
| 天氣、海洋 | NOAA (`site:noaa.gov`) |
| 醫學、健康 | NIH / Mayo Clinic (`site:nih.gov`) |
| 歷史、人物、地理 | Britannica (`site:britannica.com`) |
| 國家數據、人口 | CIA World Factbook / World Bank |
| 生物、物種 | 大學或博物館網站 |
| 統計數字 | 官方統計處、OECD |

**搜尋語法**：

```
site:nasa.gov olympus mons height
```

直接跳去權威來源,唔使喺一堆內容農場入面篩。

## ⏱ 停止規則 —— 幾時算查夠

```
✅ 一個權威來源清楚證實/否定咗個聲稱  →  停,夠
✅ 兩個獨立權威來源講法一致            →  停,夠
⚠️ 兩個權威來源互相矛盾               →  兩個都寫落解釋,講明有分歧
❌ 搵咗 5 分鐘都搵唔到                 →  停,寫「unverifiable」（見範本）
```

**最浪費時間嘅係「再查多一個確認下」。** 一個 NASA 頁面已經夠,唔使搵埋第二個。

## 開個 `sources.txt`

每次搵到嘅權威連結,貼落一個檔案,寫低係關於咩。

題材會重複出現 —— 第二次撞到同類題目,你已經有條link,慳 3 分鐘。

# 四、我嘅標準（**填一次,之後每題照跟**）

⚠️ **呢個係最影響長期評分嘅嘢。** 第一題就填好,之後唔好改。

```
────────────────────────────────
事實錯誤           = 最重,一個就足以判輸
資料過時           = 中等
唔完整但冇錯        = 輕微
太長 / 太短         = 唔影響「準確性」評分
語氣 / 文筆         = 唔影響「準確性」評分
兩個都有錯          → 比較「邊個會令讀者做錯決定」
兩個都啱            → 揀更完整嗰個;完整度一樣就講明兩個都得
────────────────────────────────
```

有咗呢張紙,**第 ③ 步（決定）由 2 分鐘變 30 秒** —— 因為你唔使每次重新諗一套標準。

# 五、解釋範本（填空,唔使由零寫）

## 標準情況

```
Response [A/B] is more accurate.

Both responses correctly state [相同部分]. The difference is
Response [X]'s claim that "[直接引用]".

This is incorrect: [正確事實]. Response [Y] makes no claims I could
not verify.

Source: [機構], "[標題]" — [連結]
```

## 兩個都有錯

```
Both responses contain errors. A states "[引用]", which is incorrect
because [原因]. B states "[引用]", which is also incorrect.

A is the better of the two because its error is less likely to mislead:
[具體點解]. B's error would lead a reader to [具體後果].

Sources: [兩個]
```

## 兩個都啱

```
Both responses are factually correct and I could not find errors in
either. A is more complete, as it also mentions [X], which is directly
relevant. B omits this but states nothing false.

Source: [確認兩者嘅來源]
```

## 查唔到

```
I could not verify [聲稱] against any authoritative source. I searched
[講你搵過乜]. As this is unverifiable rather than demonstrably false, I
weighted it as a minor concern rather than an error.
```

# 六、設定（一次過,慳好多時間）

## 文字快捷鍵

Mac：`系統設定 → 鍵盤 → 文字替換`
Windows：用剪貼簿管理員（例如內建 `Win+V` 記錄）

設呢幾個：

| 打 | 出 |
|---|---|
| `;src` | `Source: ` |
| `;both` | `Both responses correctly state ` |
| `;inc` | `This is incorrect: ` |
| `;unv` | `I could not verify this against any authoritative source. ` |

**每題慳 1–2 分鐘打字。**

## 螢幕排位

```
左邊：任務頁面        右邊：瀏覽器（查證用）
```

唔好切換視窗 —— 切一次窗慳唔到時間,但打斷咗思路要重新入返狀態。

## 開始之前

- 關通知
- 一次做 3–5 題就休息（唔好一次過做 10 題,後面會鬆手,影響一致性）

# 七、如果某一步特別慢

| 慢喺 | 通常原因 | 點救 |
|---|---|---|
| ① 讀 | 一路讀一路諗答案 | 第一次讀只做一件事：圈唔同 |
| ② 查 | 冇用 `site:` / 想查到十足肯定 | 用第三節嘅來源表 + 停止規則 |
| ③ 決定 | 冇標準,每次重新諗 | 填第四節嗰張紙 |
| ④ 寫 | 由零寫 | 用第五節範本 |
| 全部 | 攰 / 分心 | 做 3–5 題就唞,唔好死頂 |

# 八、⭐ 用範本會唔會俾人當咗係 AI？

**唔會 —— 而且啱啱相反,範本係保護你。**

要分清兩樣嘢：

| | 會唔會俾人懷疑 |
|---|---|
| **結構一致** | ❌ 唔會。專業工作本來就有固定結構（醫生病歷、驗樓報告、律師意見書） |
| **內容空泛** | ✅ **會。呢個先係 AI 嘅特徵** |

## 評審實際上係睇乜嚟判斷「呢個人有冇做嘢」

**似 AI 嘅：**

- 「It's important to note that...」「Overall, both responses have merit」呢類套話
- 文筆好靚但冇一個具體數字、冇一句引用
- 乜都 hedge,永遠唔落判斷
- 從來唔講「我查唔到」
- **交得太快**（90 秒一題）

**似人嘅：**

- 引咗對方原文（`"was formed about 10,000 years ago"`）
- 有具體數字（`50 million years, not 10,000`）
- 有一條真實連結
- 肯講「I could not verify this」
- 文字平實,唔靚仔

**你範本入面嘅括號,填嘅全部係第二類。** 每題引嘅句、查到嘅事實、貼嘅連結都唔同 —— 呢啲抄唔到、生成唔到。

> **一個填滿具體內容嘅範本,睇落比一段流暢但空泛嘅文字更似人。**

## 但可以做嘅小變化（唔使刻意)

開頭唔好每題都一模一樣,輪住用：

```
Response A is more accurate.
A is the better response.
I chose A — B contains a factual error.
A is correct; B is not.
Both are close, but A is more accurate.
A. B has one clear error.
```

偶然加一句你真實做過嘅嘢,呢個最似人：

```
I checked two sources for this because the first one was unclear.
The figure in B is close but not exact.
I initially thought B was right, but the source contradicts it.
```

⚠️ **唔好為咗「唔似 AI」而刻意寫得靚。** 靚文筆先係 AI 特徵。平實就啱。

# 九、英文唔好,點算？

**呢個唔係問題,而且可能係你估錯咗個重點。**

## 佢哋評緊嘅係你嘅判斷,唔係你嘅文筆

平台請你,係要你**捉錯處**。你用簡單英文捉到,好過用靚英文捉唔到。

**短句、簡單文法,完全冇問題。實際上仲好** —— 因為評分準則要嘅係「清楚」,唔係「優美」。

## ⭐ 更重要：揀中文任務

你嘅香港/中文雙語入口本身就係加價項目（$30–75/小時 vs 英文 $20–40）。

**喺嗰邊,你嘅語言係資產,唔係負擔。** 有得揀就揀嗰啲。

## 簡單英文句型庫（照抄,文法全部啱）

### 講判斷
```
A is more accurate.
B has a factual error.
Both responses are correct.
```

### 講相同部分
```
Both responses say [X].
Both give the same answer for [X].
The two responses agree on [X].
```

### 引用對方
```
B says "[原文]".
A states that "[原文]".
```

### 講錯咗
```
This is wrong.
This is not correct.
The date is wrong.
The number is too high.
```

### 講正確係咩
```
The correct figure is [X].
It is actually [X].
The real number is [X].
NASA says it is [X].
```

### 講來源
```
Source: NASA — [連結]
I checked NASA. It says [X].
According to USGS, [X].
```

### 查唔到
```
I could not find a source for this.
I searched but could not verify this claim.
```

## 用呢啲砌一個完整答案

```
A is more accurate.

Both responses say the mountain is Mount Everest at 8,849 m.
B also says it "was formed about 10,000 years ago". This is wrong.
The collision started about 50 million years ago.

A does not add any claim I could not check.

Source: USGS — pubs.usgs.gov/gip/dynamic/himalaya.html
```

**每一句都係簡單句。冇一個難字。** 呢個係一個完整合格嘅答案。

## 語言工具：邊啲得,邊啲唔得

| | |
|---|---|
| ✅ 查字典 / 查一個字咩意思 | 得。呢個係理解,唔係代做 |
| ✅ 拼字檢查 | 得 |
| ✅ 基本文法檢查（紅線嗰種） | 得 |
| ⚠️ AI 幫你「改順啲」 | **唔建議** —— AI 潤色出嚟嘅文,正正就係評審用嚟識別 AI 嘅特徵 |
| ❌ AI 幫你寫解釋 / 揀答案 | **唔得。呢個就係佢哋買緊嘅嘢** |

**你用簡單英文自己寫,比用 AI 潤到靚安全好多 —— 亦都真係咁。**
